▚ 体素工具链 tools/vox · 工作流说明

「方块雄鹰」的美术全面走 MagicaVoxel .vox 资产管线：所有单位造型与关卡地貌 由 Python 脚本程序化生成 .vox，Godot 侧通过导入插件 + 运行时解析器接入。 本文是工具链的总览文档；逐函数细节与最新数值以仓库内 tools/vox/README.md 为准（本文与其同源，README 更细）。

为什么直接读写 .vox 文件？ MagicaVoxel 没有 CLI、没有脚本 API、不能 headless 导出， 只当查看器与手工微调工具。所有自动化走「Python 直接读写 .vox」 （格式为 ephtracy 公开的 RIFF），纯标准库、零第三方依赖，Python 3.8+ 即可运行。

2. 标准工作流

① 改生成器（gen_units.py / gen_pirate.py / gen_scene.py）
② python 生成器.py               # 同时输出 .vox 与 _preview_*.png
③ 看预览图确认 → 双击 .vox 用 MagicaVoxel 手工精修 → 保存
④ 切回 Godot 编辑器窗口 1~2 秒   # 自动重导入生成 .mesh
⑤ 运行游戏 / 跑回归脚本          # ingame_view.gd 看游戏内实际读感
认物要看两张图：等距图（看层次）与 _sheet_enemies_topdown.png 游戏相机同向俯视图（看实际读感）—— 改完造型两张都要看，只看等距图会漏掉"俯视认不出"的问题。

3. 核心约定（改模型前必读）

  • 分辨率：所有单位按 0.3 世界单位/体素 建模（Boss 例外 0.5）， game.gd 统一 scale=0.3。「体素数 = 细节量」，敌机须与玩家机 （15×19）、Boss（17×24）同量级，否则正交 34 相机里就是几个认不出的方块。
  • 坐标系：MagicaVoxel Z-up，Godot Y-up → godot(x,y,z) = vox(x,z,y)；生成器坐标 x=左右（只画右半边再镜像）、 y=前后（小=游戏 -Z）、z=高低。
  • 朝向：地面炮台（E1H）炮管沿 -Y（look_at 让 -Z 指向目标）； 空中单位（E3~E6）机头朝 +Y（迎向玩家）。
  • 贴地对齐：由模型 AABB 自动反推偏移，改模型高度不必动 game.gd。
  • 调色板：颜色索引 ci ∈ 1..255，取色 pal[ci-1] （用成 pal[ci] 会全错/品红）；单文件上限 255 色。
  • 场景图节点：写入时自动补 nTRN→nGRP→nSHP—— Godot 导入插件的硬性要求，手写字节时务必带上。

5. 验证流程（改完模型/材质后跑一遍）

步骤命令看什么
① 冒烟-s res://tools/vox/_smoke.gd（headless）World 子树数量、体素岛 AABB 与贴海高度
② 敌机回归-s res://tools/vox/_check_enemies.gd（headless）.vox 加载、生成、更新循环、炮头 look_at
③ 量化审计-s res://tools/vox/asset_audit.gd（headless）绕序 100% 朝外 / 全硬边 / 顶面亮度<1.0（线性空间）/ 非轴法线 0%
④ 视觉验收-s res://tools/vox/asset_review.gd（需 GPU）+ pngsheet.py逐资产等距图拼成接触表一次看完
⑤ 游戏视角-s res://tools/vox/ingame_view.gd1280×720 全景 + 同尺度特写，核对认物与比例
headless / 离屏渲染三坑： ① 临时脚本必须 extends SceneTree 且 _initialize() 里显式 quit()，否则进程挂住被 timeout 杀；含 await 的函数调用方也必须 await。 ② Camera3D 先 add_child 入树再 look_at()（依赖全局变换）。 ③ 离屏渲染不能用 --headless（dummy 渲染器出不了内容），必须带 GPU 跑。

6. .vox 格式与踩坑速查

"VOX " + int32 version(150)
└─ MAIN
   ├─ SIZE : x, y, z                 模型尺寸
   ├─ XYZI : numVoxels + (x,y,z,ci)  ci ∈ 1..255，0=空
   ├─ RGBA : 256 × (r,g,b,a)         第 k 项 ↔ 索引 k+1
   ├─ nTRN/nGRP/nSHP                 场景图（Godot 导入插件硬性要求）
现象根因处理
只生成 .import 没有 .mesh缺场景图节点，插件崩write_vox 已自动补；手写字节务必带上
load(.vox) 返回 null导入链未成功排查导入；运行时有 VoxReader 回退
模型躺倒忘 Z-up→Y-upVector3i(x, z, y)
颜色全错/品红pal[ci]正确 pal[ci-1]
改了 .vox 游戏里还是旧模型编辑器未重扫描切回编辑器窗口等 1~2 秒
法线"上下颠倒"观感绕序 + generate_normals 平滑混面按 0-2-1/0-3-2 排列 + 逐面写死硬边法线（voxel_model.gd）

7. 已知限制

  • 单文件 255 色、单模型 256³（.vox 规范上限）。
  • render_iso 纯 Python 光栅化，几万体素量级可用，更大就慢。
  • _r 旋转已支持解码，但「多旋转实例组合」场景未做端到端回归。
  • 运行时依赖 .godot/imported/*.mesh，缺失时自动回退 VoxReader（可用，启动略慢）。
