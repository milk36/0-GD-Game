项目此前没有任何音频资源，因此这套音效采用程序化合成：不引入任何 wav/ogg 素材， 在运行时用代码实时生成 PCM（Godot 侧为 scripts/tetris/sfx_synth.gd， 本页用 Web Audio 复刻了完全相同的合成算法与参数常量）。 下面的按钮可以直接听到游戏里的实际音色。

2. 时序：一次完整的道具流程

碎片格出现 ──── 最后3秒滴答 ──── 玩家消掉该行 ──── 0.35s 预闪演出 ──── 清除执行
    │                  │                  │                 │                │
shard_spawn      tick0/1/2          item_get            (静默蓄力)      *_cast
                                                                        +
                                                                    item_clear

超时未消 ──→ shard_expire（配"数据丢失…"浮字）
无目标   ──→ item_fizzle （配"数据丢失…"浮字）
设计决策 A1（捕获音与冲击音分离）：item_get 在捕获瞬间响（对应浮字弹出）， *_cast 在 0.35s 预闪结束、粒子爆发的那一帧响。两者分开，玩家能听出 "先拿到 → 再炸开"两个节拍；如果合成一发，打击感会糊在一起。
设计决策 A2（道具音 = 冲击，不是 UI 提示音）：三种道具的 *_cast 都是 0.5~0.6s 的完整音景（有起音、有主体、有尾巴），而不是 80ms 的短提示音。 理由：道具是全屏级演出（粒子 + 高亮 + 计分），音太短会"配不上画面"， 且风和雷的立体声扫动本身就是"横向/竖向清除"的听觉说明。
设计决策 A3（三道具的频率分区）：风集中在 中高频噪声（气声）、 雨集中在 高频散点（1.3~2.7kHz 水滴）、雷集中在 全频 + 低频轰鸣。 三者频谱几乎不重叠，欢乐模式下道具连发时不会糊成一团，玩家闭眼也能分辨拿到了哪个。

4. 实现要点

  • 零资源依赖：全部波形由代码合成，仓库里没有也不需要任何音频文件。
  • 懒合成 + 缓存：首次播放某个 id 时才合成 PCM 并缓存（全部 11 个合计约 570ms）。
  • 异步预热：主菜单 _ready() 调 SFX.prewarm_async()， 每帧合成一个，摊平开销 —— 进游戏后首次触发不再有合成抖动。
  • 8 声道轮询：欢乐模式下多碎片格同帧熄灭、或道具连发时不会互相打断。
  • 暂停不受影响：管理器 process_mode = ALWAYS，结算界面的音效照常播放。
  • 雨滴参数硬编码：不用随机数，任何平台合成结果一致，本页与游戏内听到的完全相同。
