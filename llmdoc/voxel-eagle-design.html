1. 项目概述

定位：demo-game 游戏大厅第二款可玩小游戏。纵版滚动飞行弹幕射击， 玩法蓝本为《傲气雄鹰（Sky Force）》系列——「关卡任务奖牌制 + 星星经济局外升级 + 绳索悬停救幸存者」； 视觉与建模参考「我的世界」：所有场景、单位、特效全部由 3D 方块（体素）程序化拼装， 不依赖任何外部美术资源（贴图、模型、AI 生图均不需要），从根上降低 AI 开发渠道的美术门槛。

项目内容
玩法类型纵版滚动弹幕射击（STG）· 关卡任务制 · 局外成长
玩法蓝本Sky Force Reloaded（奖牌目标 / 星星经济 / 救幸存者）
视觉风格体素（Voxel / Minecraft-like）：3D 方块拼装 + 纯色材质 + 霓虹点缀，延续系列赛博色板
平台Godot 4.7.2 桌面端（GL Compatibility 渲染器，与大厅一致，支持 3D）
美术原则零外部资源：一切模型 = 方块坐标表 + 调色板，代码生成 ArrayMesh
目标版本M0 技术验证 → M3 交付版：3 条正式关卡 + Boss + 存档 + 机库升级

1.1 核心体验一句话

驾驶体素战机在方块海洋与岛屿上空推进：自动开火清剿敌阵、走位穿弹幕、 俯冲到幸存者头顶悬停放绳救人、捡星星回机库升级火力——用四枚奖牌（全歼 / 全救 / 全星 / 无伤）证明完美通关。

1.2 与大厅现有游戏的差异

维度俄罗斯方块（已有）方块雄鹰（本作）
渲染维度2D Canvas 自绘3D（体素网格 + 正交俯视相机）
会话结构单局无尽分关卡 + 奖牌目标 + 重复刷取
持久化仅最高分星星货币 / 升级等级 / 奖牌 / 解锁进度（本作引入首个完整存档系统）

2. 玩法规则与机制

2.1 核心循环

大厅 → 选关 → 关内：滚动推进 → 敌波 & 弹幕 → 击杀掉星星 → 悬停救幸存者
                    ↓
              关底 Boss 多阶段战
                    ↓
        结算：四奖牌判定 + 星星入账 → 机库升级火力 → 挑战下一关 / 刷奖牌

2.2 玩家机体与操作

机制规则
移动屏幕平面 8 向（WASD/方向键/手柄左摇杆），带短促加减速（加速 0.08s 到全速，松手 0.12s 停），移动时机体朝移动方向倾斜（Roll ±18°）增强体素立体感
射击自动开火（Sky Force 模式），无需按键；主炮射速 8 发/s，火力形态随升级扩展
炸弹空格：全屏敌弹清除 + 全屏伤害 + 1.5s 无敌；初始 2 枚，机库可提升携带上限
护甲3 格。被弹/撞击 −1 格 + 1.5s 无敌闪烁 + 屏幕震动；0 格坠机
坠机本关失败：结算界面保留 已得星星的 50% 入账（鼓励边打边攒），可重开本关
判定点机体视觉约 5×7 方块，但碰撞盒仅 1.2×1.2 方块（XZ 平面中心）——弹幕公平性前提

2.3 火力系统（局外升级 · 机库）

升级项共 5 条线，等级 1~8，价格曲线 cost(n) = 200 × n^1.6（取整到 50）， 星星为唯一货币。等级效果：

升级线Lv1（初始）中段形态Lv8（满级）
主炮单发直线弹Lv3 双列 · Lv5 三列+斜向五列扇面 + 两翼斜射
僚机导弹无Lv2 追踪弹×1（3s 冷却）追踪弹×4，命中溅射
磁铁吸取半径 3 格每级 +2 格半径 17 格（近全屏）
护盾无Lv2 开局附赠 1 层额外护甲（挡 1 次）2 层 + 受击后 3s 减伤
炸弹携带上限 2每 2 级 +1 上限上限 5 + 爆炸范围 +40%
设计意图：满级前「卡关 → 回低难度关刷星 → 升级 → 再战」是 Sky Force 的核心粘性循环， 数值上保证 3 关全通约需主炮 Lv4~5，刷关收益不衰减（星星掉落与表现挂钩，见 2.7）。

2.6 救幸存者（本作招牌机制）

阶段规则
① 发现幸存者（体素小人，1×2×1 格）站在地面，玩家接近 8 格内 → 头顶白色对话气泡 + 提示音
② 放绳玩家飞至其头顶正上方（XZ 偏差 ≤ 2 格）→ 垂下霓虹绳索（细长发光方块串）
③ 攀爬玩家须悬停保持 0.8s，小人沿绳上升到机腹；期间离开范围 → 绳索收回，可重来（不惩罚）
④ 完成+1000 分，HUD 奖牌图标进度 +1，小人收进机舱（缩放消失动画）
  • 每关幸存者数量：关 1 × 3、关 2 × 5、关 3 × 7。
  • MVP 设定：幸存者不会被敌弹杀死，只会因镜头滚过而错过（与关卡节奏解耦，降低挫败）；「敌人火力可击杀幸存者」列入 Hard 难度候选改动。
  • 关卡设计准则：幸存者置于轻度危险位（炮塔射界边缘、编队航线下方），救援即战术决策。

2.7 星星经济

  • 敌人死亡掉落星星（0.8~1.2 格黄色旋转方块），受重力抛散落地后随地形滚动，离开屏幕下缘即消失；磁铁范围内持续被吸向玩家。
  • 拾取 +10 分 + 星星货币 +1；奖牌「全星」要求本关收集率 ≥ 95%（含编队奖星）。
  • 坠机保留 50%，通关保留 100%——「刷关」永远正收益，但不通过奖牌无法解锁后续关卡。

2.8 奖牌与解锁

奖牌名称条件
⚔歼灭者本关击毁率 100%（可选编队计入；装饰建筑不计）
🚁救援英雄救出本关全部幸存者
★星光收集者收集本关星星 ≥ 95%
🛡完璧全程未受任何伤害（炸弹无敌期间不算受伤）
  • 解锁规则：第 N 关解锁需前 N−1 关累计奖牌 ≥ (N−1)×2 枚（关 2 需 2 枚，关 3 需 4 枚）。
  • 结算界面逐枚判定（达成点亮动画）；已获奖牌在选关界面常亮显示。

3. 视觉设计规范（体素）

3.1 基本度量与色板

  • 体素单位 VU：1.0 世界单位 = 1 方块。战斗平面为 XZ，滚动方向 +Z（敌人/地形向玩家镜头方向移动）。
  • 战斗区域宽 40 VU（玩家可动范围 X ∈ [−16, 16]，两侧留 4 VU 出界缓冲）。
  • 延续系列赛博色板，地面低饱和、战斗单位高饱和：
用途色值示例用途色值示例
环境雾/天空#050810 自机弹/友方#00f0ff 青
海面#0a2540 深蓝 敌弹/敌方强调#ff2a6d 品红
草地岛#1f6f3f 草绿 星星/得分#ffe600 黄

3.2 体素建模规范

  • 模型 = 方块表：相对坐标 + 调色板索引。代码内以字符画定义（见 6.3），构建时合并为单个 ArrayMesh。
  • 面剔除优化：被 6 邻居包围的面不生成顶点（模型加载时一次性烘焙）。
  • 自发光：敌弹/绳索/星星用 BaseMaterial3D.emission 全亮纯色（GL Compatibility 无 Bloom，以高饱和纯色 + 深色地面拉开对比，不追求辉光）。
  • 敌弹视觉规格：0.7 VU 品红方块 + 白色内核 0.35 VU（双层叠加提升可读性），缓慢自转。

3.5 相机与光照

项方案说明
相机正交（Orthographic），size 24 VU，俯角 68°，位于玩家后上方，镜头微向前下压既看到方块侧面立体感，又保证弹幕落点可读；M0 用 90° 纯俯视做 A/B 对比后定稿
判定映射碰撞一律在 XZ 平面计算，忽略 Y（高度只做视觉）斜视角下"子弹看起来在哪"与"判定在哪"必须一致，靠正交+固定俯角规避透视误差
主光DirectionalLight3D，暖白，从相机侧前方入射，开阴影地面单位投影是高度与位置的核心可读性来源；若 M0 性能不达标则关闭阴影改用深色"假阴影"贴方块
环境WorldEnvironment：深蓝雾（距离淡出）+ 低强度环境光屏幕上缘用雾吞没出生点，敌机"从雾中现身"

3.6 特效（全部方块化）

  • 爆炸：6~14 个 0.5 VU 方块碎片抛物线飞散 + 旋转 + 缩放消失（0.6s），颜色取自被毁单位调色板；大单位爆两次（外壳+内核）。
  • 救援绳索：0.3×0.3 VU 白色发光方块串（8 节），逐节垂下/收回；小人攀爬为匀速上移。
  • 星星：绕 Y 轴旋转的 1 VU 黄色方块，落地弹跳两次后静止轻浮动。
  • 炸弹：全屏白色闪光 0.2s + 从玩家位置扩散的青色方块冲击环。
  • 中弹：屏幕边缘品红 vignette + 相机震动 0.25s。
  • 海面波纹：海面由 4×4 VU 大方块拼成，shader 按 UV 相位做明暗波动（无贴图，纯顶点/片元色计算）。

const PLAYER_TOP := """
   · ▲ ▲ ·
  ▲ ◆ ◆ ▲

▲ ■ ◆ ◆ ■ ▲
▲ ■ ◆ ◆ ■ ▲

  ▲ ■ ■ ▲
   ■ · ■

# 每层一张字符画 + 层高表 → 方块表 [(x,y,z,palette_idx), ...]
# voxel_model.gd 构建：遍历方块 → 6 邻居剔除内面 → 同色段合并 → SurfaceTool → ArrayMesh
# 运行时只 new MeshInstance3D 共享 mesh，零每次构造成本
  • 所有单位模型集中在 models.gd，修改造型 = 改字符画，无任何外部文件依赖。
  • 地形块：预生成若干 40×24 VU 的"地形图案"（海面/岛/建筑），按关卡表顺序循环拼接。

6.4 子弹与性能预算

  • 自机弹/敌弹各一个 MultiMeshInstance3D（容量 256/512），子弹数据存扁平数组（pos/vel/ttl/type），每帧批量写 instance_transform。
  • 碰撞：敌弹→玩家 O(n)；自机弹→敌人 空间网格分桶（敌人活跃数 < 40，桶宽 8 VU）；判定均用 XZ 平面 AABB/圆。
  • 性能目标：60 FPS @1080p（GL Compatibility）；压测基准：同屏敌弹 300 + 自机弹 150 + 碎片 200 + 阴影开启，M0 验证不过则降级顺序：关阴影 → 降碎片上限 → 敌弹纹理合并。

9. 风险与待确认决策点

① 相机俯角 vs 弹幕可读性（M0 必须先定）
68° 斜俯视体素立体感强，但斜视角下"子弹看着在 A 判定在 B"是弹幕游戏大忌。 对策：正交相机 + 固定俯角 + 碰撞只算 XZ 平面，把透视误差压到可忽略；M0 做黑白弹可读性实测， 不达标退回 90° 纯俯视（立体感改由方块高度差与阴影表达）。
② GL Compatibility 的 3D 阴影开销
本作是大厅第一个 3D 游戏，方向光阴影在低端机的开销未知。降级路径已定（假阴影贴片）， M0 压测数据说话，不猜测。
③ 体素风格的"廉价感"风险
纯方块拼装容易显单调。对策：强轮廓色对比（深地面/亮单位）、全员待机动画（浮动/自转/尾焰）、 爆炸碎片与救生绳索两个"高辨识度方块特效"撑住观感下限；不追求 Minecraft 官方素材相似度（避免商标/素材风险，用通用体素风）。
④ 「100% 歼灭」奖牌的体验强度
敌人滚出屏幕即损失奖牌，对新手压力大（Sky Force 同款设计）。首发 3 关里仅关 2、3 有高逃逸敌人， 关 1 敌人以地面固定为主，保证首关奖牌可达性。若实测挫败感过强，备选方案：逃逸敌人计入分母但允许 1 个容错。
⑤ 数值平衡依赖试玩
升级价格曲线、Boss 血量、弹幕密度在纸面上只能给初值，验收后需要 2~3 轮试玩调参—— 波次表/弹型参数/升级表已全部数据化，调参不动代码。
待确认项（实现前与需求方对齐）： (a) 游戏名「方块雄鹰」是否采用；(b) 机体 3 格护甲制（非 Sky Force 原版的一击坠机）是否符合预期； (c) 幸存者 MVP 不可被击杀的取舍；(d) 双人同屏（Sky Force 特色）是否列入后续版本。

  • 部分枚举常量在脚本解析器中不可直接引用（GeometryInstance3D.SHADOW_CASTING_OFF、HorizontalAlignment.CENTER），改用数值 + 注释；而 Environment.fog_mode、Camera3D.projection 赋数值运行时通过，但 Label.alignment 赋 int 运行时报错——枚举属性行为不一致，逐个实测为准；
  • PackedByteArray 不能赋 bool（shrink[i] = 1 if b else 0）；
  • Packed 数组索引返回 Variant，:= 推断失败必须显式类型（var d: Vector3 = eb.pos[i] - p）；
  • Basis.rotated() 是实例方法，Basis.rotated(Basis.IDENTITY, ...) 静态式调用会报错；
  • MultiMesh 未用实例必须初始化零缩放 transform，swap-remove 后死亡位也要置零，否则残影。
